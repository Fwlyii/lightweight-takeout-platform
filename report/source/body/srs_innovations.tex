\textbf{状态约束：}

1. 任何角色不得越级写入后续状态，Service 层必须校验当前状态、操作者和目标状态。

2. 已绑定骑手后，商家不能直接把订单设置为已完成；完成动作由顾客确认或系统超时规则触发。

3. 每次状态变化写入状态历史，至少记录订单、原状态、新状态、操作者、时间和原因。

4. 订单取消、退款和异常处理必须在事务边界内同步处理钱包、优惠券、积分、库存与统计口径。

\subsection{营销、个性化和智能交互规则}

\textbf{优惠叠加候选规则：}默认每单最多叠加一张平台券和一张商家券，会员券是否可继续叠加、积分是否可抵扣现金由小组审核后确定。后端返回完整试算明细，前端不得自行决定最终应付金额。

\textbf{钱包与积分规则：}钱包为教学项目中的模拟资产，不对接真实充值和提现；任何余额变化均以流水为准。积分比例、有效期和抵扣上限使用后台配置，禁止散落在控制器或前端常量中。

\textbf{个性化规则：}系统只在用户授权后使用历史行为形成推荐偏好，用户可查看、修改和清除偏好；每日幸运色只影响 UI，不参与价格或权益计算。

\textbf{智能功能确认规则：}AI 推荐、图片识别和语音点单只能生成候选或草稿，所有影响购物车、地址、优惠、支付和下单的操作必须由用户显式确认。

\textbf{外部服务降级：}地图、AI、语音、识图或对象存储不可用时，系统保留文字搜索、手工选餐、文本地址和基础订单能力，并返回可理解的错误提示。

\subsection{评价、商品展示与数据看板规则}

评价资格来源于已完成订单，禁止未购买用户评价；商家回复与管理员治理分别授权，隐藏或恢复评价必须保留审计记录。评论编辑时限、图片数量和敏感内容规则待小组确认。

商品详情需要保存活动快照与成交价格，避免商家后续修改原价、折扣、限购或图片后影响历史订单。月售和热销排名只统计有效订单，取消订单不计入销量。

顾客看板按月、品类和商家统计本人有效消费；商家看板只展示所属店铺；管理员看板展示平台汇总。取消订单不计营业额，退款订单按净额统计，所有看板接口支持时间范围参数。

\subsection{明确排除的功能}

本轮不实现人工客服电话、AI 客服转人工、好友拼单和通过 ID 互赠外卖。智能推荐与智能客服咨询不得被描述为人工客服替代流程；真实支付清算、真实骑手薪资结算和真实保险管理也不在教学项目范围内。
