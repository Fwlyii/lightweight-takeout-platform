# 高德地图接入（课程演示）

## 配置与数据

- 后端环境变量：`AMAP_JS_KEY`、`AMAP_SECURITY_CODE`、`AMAP_WEB_KEY`。前端仅通过 `/api/maps/config` 取得可公开的 JS Key，安全密钥通过限定路径的后端代理使用。
- 本地私密配置可放在根目录 `.env.local`（Git 已忽略）；运行后端时需显式加载环境变量。不要将此文件加入版本管理或前端构建。
- 既有数据库先备份，再运行 `elm_bk/db/migrations/006_map_coordinates.sql` 一次。它只增加 10 个可空字段，不修改历史地址、订单或猜测点位。新建数据库的完整 schema 已包含这些字段。
- 坐标统一为 GCJ-02；浏览器 WGS-84 定位经高德转换后才使用。默认天津校园仅是地图视窗中心，不是用户或商家位置。
- 高德网页 Key 的域名白名单需要包含实际访问域名；不要通过清空白名单来解决本地调试问题。生产域名当前为 `elm-demo.pages.dev`。

## 演示流程

1. 商家申请新店先搜索/选择地图位置，再补充店铺资料；已有店铺在商家详情的“店铺位置”重新选点并保存。
   后端同样强制新店申请携带有效经纬度和地图地址，缺失时返回业务校验错误（409）；不能只填写文字地址绕过。
2. 新增/编辑收货地址点击“地图位置”，确认后可在详细地址末尾补充楼栋门牌。
3. 首页点击“选择送达位置”，使用设备定位、搜索 POI 或点击地图，再确认。拒绝定位不影响搜索选址。
4. 首页、分类、AI 推荐、店铺详情使用同一套真实坐标距离口径。距离标为直线距离，送达时间仍是备餐与行驶估算，不是高德承诺时效。
5. 店铺详情可按坐标导航；骑手接单后按任务阶段导航到商家或收货位置，旧地址缺少坐标时保留文字搜索兜底。骑手接单前仍不返回收货坐标。

地图请求有超时、短时缓存和总调用限制；地图加载失败可重试，定位失败可手动选址。不保证网络或第三方服务永远可用。演示前建议使用实际展示设备检查域名、浏览器定位权限与剩余额度。

## 验证与回滚

前端 `npm --prefix elmclient test` / `npm --prefix elmclient run build`；后端 Java 17 / Maven `mvn test`。

发布采用 Railway 上传和 Cloudflare Pages 部署，不需要 Git 提交。回滚优先切换前后端到改造前部署，保留新增可空列以免丢失新数据；不要默认恢复整库。改造前备份与发布记录保存在工作区外的 `map-rollback-20260916.kzTiUi` 目录。

2026-09-16 经用户授权，公网 12 家演示店铺绑定了实际高德 POI，地址注明“演示店铺”，不代表与对应真实商户有关联。只更新店铺地址和地图字段，保留账号、商品、订单与用户收货地址；该目录另存更新前后 JSON 和仅回滚店铺位置的 SQL。
