\chapter{项目部署与运行说明}
\section{部署依据与适用环境}
本章根据当前仓库的 \code{docs/DEPLOYMENT.md} 和 \code{docker-compose.demo.yml} 整理本地演示步骤。Docker Compose 会同时启动前端、后端和 MySQL，并集中管理版本和网络配置。启动过程中按日志检查服务状态。

表\ref{tab:deploy-troubles}列出常见排查路径。环境需要 Git、运行中的 Docker 和 Compose v2，自动生成配置还需要 zsh 与 OpenSSL。首次构建会下载镜像、npm 和 Maven 依赖，启动前检查 18081、18080、13306 三个端口。手动开发模式使用 Node.js 20、JDK 17 和 MySQL 8。
\section{获取代码与准备配置}
\begin{lstlisting}
git clone --branch main https://github.com/Fwlyii/lightweight-takeout-platform.git
cd lightweight-takeout-platform
zsh scripts/ensure-demo-env.sh
\end{lstlisting}
配置脚本在本地 \code{.env} 中生成随机 \code{JWT_SECRET}，已有有效密钥会保留。使用其他 shell 时，可参照根目录 \code{.env.example} 手工填写，并使用 \code{openssl rand -hex 64} 生成本地密钥。密钥只用于本地运行，报告记录配置方式，不写入密钥内容。

外部能力按需设置 \code{DEEPSEEK_API_KEY}、\code{DASHSCOPE_API_KEY} 以及视觉和语音模型变量；高德选址使用 \code{VUE_APP_AMAP_KEY}，改动后需重新构建前端。浏览和普通点餐不依赖这些密钥；可选入口未配置时，应同时检查提示和普通搜索等替代路径。
\section{构建、启动与检查}
\begin{lstlisting}
docker compose -f docker-compose.demo.yml up -d --build
docker compose -f docker-compose.demo.yml ps -a
docker compose -f docker-compose.demo.yml logs --tail=100 mysql migrate backend frontend
\end{lstlisting}
表\ref{tab:local-endpoints}列出启动后可访问的入口。首次启动时 MySQL 创建 \code{elm_v2} 并导入结构和演示数据，迁移任务随后处理订单名称快照、购物车备注等更新。\code{migrate} 正常完成后显示 \code{Exited (0)}，这是一次性任务的预期结果。后端以 JDK 17 运行，前端用 Node.js 20 构建后由 Nginx 提供页面，并通过同源代理访问后端。

\section{演示角色与验收顺序}
本地演示数据库提供 \code{demo_user}、\code{demo_merchant}、\code{demo_rider}、\code{demo_rider_candidate} 和 \code{demo_admin} 等账号，初始密码记录在部署文档中。验证不同角色时分别使用浏览器会话，切换身份不会带入上一账号的缓存和登录状态。

验收可以从顾客浏览、加购、选择外送或自取、提交和模拟支付开始，再沿商家接单备餐、骑手配送、顾客确认收货继续。随后补测取消、库存不足、未登录访问和外部服务不可用，跨商家商品分别结算。页面打开后，还需逐项确认数据库写入、角色权限和订单推进。
\section{停止、恢复与数据维护}
\begin{lstlisting}
docker compose -f docker-compose.demo.yml stop
docker compose -f docker-compose.demo.yml start
\end{lstlisting}
当前配置由 Compose 管理 MySQL 数据卷名称。重建容器前先确认数据持久化和备份方案，日常更新应保留容器数据并按备份方案操作。初始化 SQL 只在数据目录首次创建时执行，已有环境按迁移脚本的适用条件更新；\code{runtime-uploads/} 也需要和数据库一起纳入备份。

\section{不使用 Docker 的开发模式}
准备 MySQL 8 后，在新库按部署文档导入表结构、演示种子及指定迁移，配置数据库连接、\code{JWT_SECRET} 与 \code{SERVER_PORT=18080}。Maven 不会自动读取 \code{.env}，应通过终端环境或 IDE 运行配置提供变量。后端执行 \code{./mvnw spring-boot:run}；前端在 \code{elmclient} 执行 \code{npm ci}、\code{npm run serve}，开发地址以终端输出为准。前端默认连接本机 18080 后端，修改时使用 \code{VUE_APP_API_BASE_URL}。
