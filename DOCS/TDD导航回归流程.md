# 导航问题的 TDD 流程

## 阶段边界

所有新增或修改的测试代码、断言、测试夹具和 mock **只能放在 RED 阶段及 RED 提交**。GREEN 和 REFACTOR 不修改测试；三个阶段都执行测试。若实现期间发现遗漏场景，先回到新的 RED 补充用例并复现失败，再继续 GREEN，不能通过删除用例、跳过测试或放宽断言使测试变绿。

提交信息须先获得项目负责人的确认。可以先在本地保存分阶段补丁和运行结果，确认后按 RED、GREEN、REFACTOR 顺序提交；三个阶段完成后再一起推送，不单独推送故意失败的 RED 版本。

## RED：复现问题并冻结全部测试

1. 记录基线提交、页面地址、进入路径、点击顺序、预期返回位置和实际返回位置。
2. 先通过页面按钮复现，而不只测试直接打开链接或刷新。
3. 检查同类入口：页面返回按钮、全局返回按钮、浏览器后退、功能页切换、带参数的详情页以及直接访问。
4. 将本轮所有回归用例加入 `elmclient/tests/navigation.test.mjs`，暂不修改生产代码。
5. 验证失败来自行为不符合预期，而不是语法错误、导入错误或测试环境失效；保留已有正确行为作为对照。

本轮共 40 项新增测试：

- AI 主页面、筛选、语音、识图之间切换后，返回能退出到原业务页。
- AI 内部切换和识图关键词跳转不不断追加历史；浏览器后退能离开整个 AI 流程。
- AI 子页直接打开后，两次返回可到首页；主页面无历史时也有明确出口。
- 旧 AI 历史、登录注册页、未知地址、外部地址、跨工作端地址不能成为退出目标。
- 有效来源及查询参数保留；退出后旧组件的第二次返回点击不能再次跳转。
- 通用返回、商家详情、订单详情、钱包、通知、商家申请、商家评价、商品管理、管理员页面直接打开时都有站内兜底。
- 骑手共享通知页返回骑手工作台。
- 购物车“返回商家”按有效商家 ID 返回；非法或缺失 ID 回首页。
- 通用返回不退回登录、支付及支付完成页，也不退回自身或未知路由。

测试读取实际路由表和 Vue 文件中的返回事件/函数，使用确定性的历史栈模拟器运行；它们不等同于真实浏览器验收，所以 GREEN 后仍须完成下方手动路径检查。

从 `elmclient` 目录执行：

```bash
node --test tests/navigation.test.mjs
npm test
shasum -a 256 tests/navigation.test.mjs
```

## GREEN：最小修复，不改变测试

- AI 内部功能切换使用 `replace`；功能页返回 AI 主页面也使用 `replace`。
- AI 主页面只返回有效的非 AI 站内来源，无有效来源则回首页。
- 所有直接依赖浏览器历史的页面返回入口使用共用的来源校验和业务兜底。
- 购物车使用“继续选购”文案：有有效商家 ID 时到该商家，否则到首页，不把任意上一页当作商家页。

重新执行上述测试命令及 `npm run build`。本轮 GREEN：40 项导航回归全通过，全量 108 项通过，生产构建通过；测试哈希与 RED 相同。

真实浏览器验收路径：

1. 首页 → AI → 筛选 → 语音 → 返回 → 返回，应到首页。
2. 首页 → AI → 子功能 → 浏览器后退，应回首页。
3. 直接打开/刷新 AI 子页 → 返回 → 返回，应离开 AI，不循环。
4. 带商家 ID 的购物车 → 继续选购，核对 URL 的商家 ID；无商家 ID 时返回首页。
5. 单独打开详情页且无站内历史时，返回到对应列表或工作台。

不为导航验收授权摄像头或麦克风，不创建真实订单或支付。

## REFACTOR：整理规则，保持行为与测试不变

- 将业务兜底路由集中为声明式映射，将禁止返回的流程页集中为集合。
- 页面只调用统一返回入口，不再分散使用无校验的 `router.back()` 或 `router.go(-1)`。
- 测试文件保持 RED 时的内容，重新跑全量测试、生产构建和关键浏览器路径。
- 用 `git diff --check` 检查补丁；提交前核对 GREEN、REFACTOR 的变更文件列表不含任何测试文件。

本轮 REFACTOR 实测：全量 108 项通过，生产构建通过，测试冻结哈希未变化。浏览器已验证连续两次页面返回、AI 子功能的浏览器后退、无历史商家详情返回，以及购物车按商家 ID 返回。

## 完成条件

必须同时满足：先有可解释的 RED 失败、GREEN 修复使同一批测试全绿、REFACTOR 未改变测试、生产构建通过、真实按钮路径验收通过。报告应区分自动测试与浏览器验收，不能用“构建成功”替代交互验证。
