## 测试验证什么

`AuthenticationJourneyTest` 使用真实 Spring Boot 应用和 MockMvc：HTTP 请求经过实际安全过滤器、
控制器、服务与 MyBatis；不 Mock 注册成功、密码校验、数据库写入或 JWT 签名。

| 场景 | 预期行为 |
| --- | --- |
| JSON 或 multipart 注册时未上传头像 | 注册成功，返回且入库平台默认头像 |
| 客户端伪造权限、头像 URL、启用状态 | 注册只获得 USER 权限，敏感字段由后端确定 |
| 新用户注册后登录 | 能获得签名有效的 JWT，并访问受保护接口 |
| 使用注册手机号登录 | 能登录同一个账号，兼容原有用户名登录 |
| 重复用户名、重复手机号、用户名前后空格 | 拒绝重复注册，不产生多余账号或个人信息 |
| 手机号、用户名及密码的缺失、格式和长度边界 | 返回 400，不写入账号 |
| 分配基础权限失败 | 整笔注册回滚，不留下孤立账号 |
| 顾客、商家、骑手、管理员从对应端登录 | JWT 只包含本次会话的一个权限，并绑定登录端 |
| 骑手等工作账号从错误端登录 | 后端拒绝，即使密码正确或账号保留历史 USER 权限 |
| 普通顾客进入商家或骑手申请入口 | 只签发申请权限，不直接授予商家或骑手工作权限 |
| 错误密码、不存在的账号、禁用账号 | 不签发令牌，返回适当的认证失败结果 |
| 登录端参数缺失或不合法 | 返回 400 |
| 登录后账号被禁用、令牌过期 | 后续受保护请求被拒绝 |

错误密码与不存在账号的外部提示应一致，避免泄露账号是否存在。
这组测试不包含后续店铺开通、骑手审核、购物车和订单功能。

## 测试环境和复现

`AuthenticationTestEnvironmentTest` 单独确认应用能启动、数据库确为内存 H2、真实 MyBatis 查询可执行。
测试类用高优先级测试属性固定数据库连接，避免本机 MySQL 环境变量覆盖测试配置。
`auth-schema.sql` 仅包含生产库的四张账号相关表，不加载演示数据。
每个用例清理自己的内存表，互不依赖执行顺序。

JDK 17 环境下，在仓库根目录执行：

```bash
cd elm_bk
./mvnw -Dtest=AuthenticationTestEnvironmentTest test
./mvnw test
```

没有本机 JDK 时，可在 `elm_bk` 目录使用 Maven 的 JDK 17 容器：

```bash
docker run --rm \
  -v "$PWD":/workspace \
  -v authentication-maven-cache:/root/.m2 \
  -w /workspace \
  maven:3.9.9-eclipse-temurin-17 mvn -B test
```

首次运行需要下载依赖；测试不需要启动项目的 MySQL、前端或公网服务。
H2 用于账号流程的快速集成测试，不能代替 MySQL 并发、约束、方言以及浏览器交互验收。

## P14：整理职责、补充验收和登录页面接入

这里区分两件事：代码整理是 REFACTOR；此前未覆盖的并发约束、当前账号接口等，
属于追加验收与实现，不把新增行为都声称为“纯重构”。

新增 `AuthenticationHardeningTest` 先实际运行：14 项中 6 项断言失败、8 项通过，
没有启动错误或测试跳过。失败分别是数据库用户名/手机号唯一约束、两个并发注册场景、
缺少 multipart 参数的错误响应，以及当前账号查询接口。
见 [修复前结果](./authentication-hardening-before.txt)。

之后进行了以下修改：

- 生产建库 SQL 和 H2 测试 schema 同步增加唯一索引；不能只给测试库加约束。
  六个并发注册请求由数据库决定一个成功，其余返回 409；失败事务不留下账号、个人资料或权限记录。
- `CurrentUserService` 只从已经验证的安全上下文取得身份；查询当前账号不能使用请求里的 `userId`。
- 注册和当前账号查询共用 `ProfileViewFactory`，显式列出可返回字段，不返回密码散列。
- `TokenProvider.readSession()` 统一签名和声明解析，`VerifiedSession` 统一检查账号状态、权限与更新时间。
  `JWTFilter` 每次请求只解析一次令牌、查询一次账号，不再重复验签和读取数据库。
  旧方法保留为委托包装，方便后续 WebSocket 功能接入同一规则。
- 前端登录流程移入 `authenticationClient.js`：拿到令牌后，再用该令牌查询真实账号，
  两步都成功才保存完整登录状态。资料读取失败、身份发生变化时清理会话。
  页面仅负责输入、忙碌状态、提示和路由跳转；登录角色在请求期间不可切换。
- 追加了角色策略和令牌规则回归测试，以及前端登录失败清理、申请身份、跳转安全等测试。

### 给组员的接入提示

1. 合并后从 `Fwlyii/lightweight-takeout-platform` 的最新 `main` 开发，不用沙盘快照覆盖整个目录。
2. 使用旧数据库的成员，先按 [账号联调说明](./authentication-preview.md) 检查并执行唯一约束迁移。
   已有重复数据时需要人工确认，不会自动删账号。
3. 注册、登录、当前账号查询由这一组代码提供；后续个人资料编辑、管理员管理等接口在此基础上扩展，
   不要直接用快照中的大控制器替换当前小控制器，否则会丢掉事务和安全改进。
4. 独立联调入口复用正式的 Login、Register、HTTP 客户端和后端；账号验收页不伪装成商家或骑手业务工作台。
   完整 `App.vue` 仍依赖后续业务页面，本阶段没有宣称默认整站入口已经构建通过。
