## 测试验证什么

`AuthenticationJourneyTest` 使用真实 Spring Boot 应用和 MockMvc：HTTP 请求经过实际安全过滤器、
控制器、服务与 MyBatis；不 Mock 注册成功、密码校验、数据库写入或 JWT 签名。

| 场景 | 预期行为 |
| --- | --- |
| JSON 或 multipart 注册时未上传头像 | 注册成功，返回且入库平台默认头像 |
| 客户端伪造权限、头像 URL、启用状态 | 注册只获得 USER 权限，敏感字段由后端确定 |
| 新用户注册后登录 | 能获得签名有效的 JWT，并访问受保护接口 |
| 使用注册手机号登录 | 能登录同一个账号，兼容原有用户名登录 |
| 重复用户名、重复手机号、用户名前后空格 | 拒绝重复注册，不产生多余账号或个人信息 |
| 手机号、用户名及密码的缺失、格式和长度边界 | 返回 400，不写入账号 |
| 分配基础权限失败 | 整笔注册回滚，不留下孤立账号 |
| 顾客、商家、骑手、管理员从对应端登录 | JWT 只包含本次会话的一个权限，并绑定登录端 |
| 骑手等工作账号从错误端登录 | 后端拒绝，即使密码正确或账号保留历史 USER 权限 |
| 普通顾客进入商家或骑手申请入口 | 只签发申请权限，不直接授予商家或骑手工作权限 |
| 错误密码、不存在的账号、禁用账号 | 不签发令牌，返回适当的认证失败结果 |
| 登录端参数缺失或不合法 | 返回 400 |
| 登录后账号被禁用、令牌过期 | 后续受保护请求被拒绝 |

错误密码与不存在账号的外部提示应一致，避免泄露账号是否存在。
这组测试不包含后续店铺开通、骑手审核、购物车和订单功能。

## 测试环境和复现

`AuthenticationTestEnvironmentTest` 单独确认应用能启动、数据库确为内存 H2、真实 MyBatis 查询可执行。
测试类用高优先级测试属性固定数据库连接，避免本机 MySQL 环境变量覆盖测试配置。
`auth-schema.sql` 仅包含生产库的四张账号相关表，不加载演示数据。
每个用例清理自己的内存表，互不依赖执行顺序。

JDK 17 环境下，在仓库根目录执行：

```bash
cd elm_bk
./mvnw -Dtest=AuthenticationTestEnvironmentTest test
./mvnw test
```

没有本机 JDK 时，可在 `elm_bk` 目录使用 Maven 的 JDK 17 容器：

```bash
docker run --rm \
  -v "$PWD":/workspace \
  -v authentication-maven-cache:/root/.m2 \
  -w /workspace \
  maven:3.9.9-eclipse-temurin-17 mvn -B test
```

首次运行需要下载依赖；测试不需要启动项目的 MySQL、前端或公网服务。
H2 用于账号流程的快速集成测试，不能代替 MySQL 并发、约束、方言以及浏览器交互验收。
